# Политика безопасности

> [English version](SECURITY.md)

## Поддерживаемые версии

| Версия | Исправления безопасности |
|---|---|
| 4.1.x | Поддерживается |
| 4.0.x | Только критические исправления до следующего minor-релиза |
| Более ранние | Не поддерживаются |

## Сообщение об уязвимости

Не публикуйте exploit, секреты, адрес сервера или приватную конфигурацию в открытом issue. Используйте GitHub Private Vulnerability Reporting во вкладке Security. Если функция недоступна, свяжитесь с сопровождающим приватным способом из его профиля GitHub и запросите зашифрованный канал.

Укажите версию установщика, компонент, шаги воспроизведения, влияние и возможное исправление. Не тестируйте системы, которыми вы не владеете и не управляете.

## Целевые сроки ответа

- подтверждение получения — 3 рабочих дня;
- первичная оценка — 7 рабочих дней;
- согласованное раскрытие после исправления или в оговорённый срок.

## Если секреты скомпрометированы

1. Ограничьте сетевой доступ и сохраните журналы.
2. Смените секреты PostgreSQL, TURN, регистрации, MAS и LiveKit.
3. Отзовите затронутые устройства/сессии Matrix и данные ntfy.
4. Замените данные VLESS и проверьте `/usr/local/etc/xray/config.json`.
5. Изучите журналы федерации/администрирования и восстанавливайтесь только из доверенного backup.

## Защита цепочки поставки

- устанавливайте из GitHub-релиза и проверяйте `SHA256SUMS`;
- внешние root-установщики закреплены commit и checksum;
- GitHub Actions закреплены полным SHA commit;
- образы закреплены одновременно version tag и OCI digest;
- еженедельные workflows проверяют загрузки и запускают Trivy, Gitleaks и zizmor.

## Защита хоста

Используйте SSH-ключи, ограничьте административные IP, регулярно обновляйте хост, шифруйте внешние backup и следите за диском. До включения UFW установщик определяет и сохраняет текущий SSH-порт через `sshd -T`.
