# Резервное копирование и аварийное восстановление

> [English version](BACKUP.md)

Состояние Matrix не ограничивается файлом `homeserver.yaml`. Полный набор для восстановления должен содержать базу PostgreSQL Synapse, signing key, секреты регистрации/TURN/MAS, базу MAS при её использовании, конфигурацию и медиахранилище.

## Создание и проверка backup

```bash
sudo ./install-matrix.sh backup
sudo ./install-matrix.sh verify-backup latest
```

Копии хранятся в `/root/matrix-server/data/backups/<timestamp>/`:

- `synapse.dump` — дамп PostgreSQL в custom format;
- `mas.dump` — дамп MAS, если компонент установлен;
- `configuration.tar.gz` — `.env`, Compose, signing keys и конфигурация компонентов;
- `MANIFEST.txt` — версия установщика, домены, причина и список образов;
- `SHA256SUMS` — контрольные суммы, проверяемые перед restore.

`media_store` намеренно исключён из архива из-за возможного большого размера. Копируйте его отдельно через snapshots, restic, borg или репликацию в объектное хранилище.

## Что нельзя потерять

| Данные | Последствия потери |
|---|---|
| База Synapse | Потеря комнат, аккаунтов, устройств и состояния |
| `*.signing.key` | Сервер не сможет подтвердить непрерывность идентичности в федерации |
| `.env` и конфигурация MAS | Потеря секретов БД, TURN, OIDC и шифрования |
| База и ключи MAS | Сессии и аккаунты аутентификации могут стать недоступны |
| `media_store` | Исчезнут загруженные файлы и миниатюры |

Копируйте backup за пределы VPS. Копия рядом с рабочей базой не является аварийным восстановлением.

## Восстановление на текущем сервере

```bash
sudo ./install-matrix.sh restore /secure/offsite/20260820-120000
# или последняя локальная копия
sudo ./install-matrix.sh restore latest
```

Команда проверяет SHA-256 и безопасность tar-архива, создаёт pre-restore backup существующего стека, останавливает приложения, восстанавливает PostgreSQL/MAS и запускает полную диагностику.

## Восстановление на новом сервере

1. Подготовьте чистый поддерживаемый VPS и направьте на него прежние DNS-имена.
2. Запустите базовую установку с теми же доменами, чтобы установить Docker, Nginx, Certbot и UFW.
3. Передайте каталог backup и отдельную копию media store по защищённому каналу.
4. Выполните `restore <directory> --yes`.
5. Верните `data/synapse/media_store` с владельцем `991:991`.
6. Перевыпустите TLS-сертификаты и запустите `diagnose`.
7. До переключения трафика проверьте вход, историю сообщений, медиа, федерацию и звонки.

## Учебное восстановление

Проверяйте восстановление перед каждым крупным релизом и хотя бы раз в квартал. Ручной workflow `E2E deployment` выполняет цикл backup/restore на одноразовом runner.

Backup содержит секреты. Шифруйте копии, ограничивайте доступ пользователем `root` и задайте политику хранения.
